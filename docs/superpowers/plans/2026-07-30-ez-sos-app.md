# EZ SOS Full App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Spec to follow:** [docs/superpowers/specs/2026-07-30-ez-sos-app-design.md](../specs/2026-07-30-ez-sos-app-design.md)
>
> **Context:** Phase 1 (Dev Container + skeleton) is done. Work inside the Dev Container for Pebble C/PKJS builds. Android companion builds on the host or an Android SDK environment (may be outside the Pebble container).

**Goal:** Turn the EZ_SOS skeleton into a working SOS watchapp (C + PebbleKit JS) with configurable triggers, unlimited contacts, GPS + SMS (silent preferred, Check-phone fallback), plus an Android companion that alarms the watch on SMS replies from enabled contacts.

**Architecture:** Phone-owned SOS. Watch = trigger/status/alarm UI. PKJS = settings HTML, localStorage, GPS, `sms:` fallback. Android companion = silent SMS, inbound match, `INBOUND_ALERT`. iOS out of scope.

**Tech Stack:** Core Devices pebble-tool / Pebble C SDK, PebbleKit JS, custom config HTML, PebbleKit Android (Kotlin), Android SMS + location APIs.

## Global Constraints

- Follow the design spec; do not invent alternate product behavior
- Platforms: `aplite`, `basalt`, `chalk`, `diorite`, `emery`
- Default trigger mode: `confirm`
- No GPS → do not send; status `no_gps`
- Fallback watch text: **Check phone**
- Inbound: enabled-contact number match only; Android only
- Document: **iOS makes inbound SMS→watch alarm impossible**
- Keep UUID in sync: `package.json` ↔ Android (`cf79bb9f-ab43-4848-81b6-d1c1ae6a9226` unless explicitly regenerated everywhere)
- Do not commit secrets; do not publish stores in this plan

## Task 3: PKJS — settings page + outbound SOS

**Files:** `src/pkjs/index.js`, `src/pkjs/config.html`

- [x] Implement `config.html`: list contacts (name, phone, enabled), add/edit/remove, message prefix, trigger mode
- [x] `showConfiguration` → `Pebble.openURL` (data URL or bundled/hosted config — pick one that works with `pebble emu-app-config` and phone settings)
- [x] `webviewclosed` → parse settings → `localStorage`
- [x] On `ready` and after save: `Pebble.sendAppMessage` with `TRIGGER_MODE` and `SETTINGS_JSON`
- [x] On `appmessage` `SOS_REQUEST`:
  1. Load settings; if no enabled contacts → `STATUS` `no_contacts`
  2. `navigator.geolocation.getCurrentPosition` (high accuracy); on fail → `STATUS` `no_gps`
  3. Build body = prefix + lat/lon + Maps link
  4. Call `trySilentSms(contacts, body)` stub returning false under pure PKJS
  5. Else open `sms:` URL per enabled contact; `STATUS` `check_phone`
  6. If a future hook reports silent success → `STATUS` `sent`
- [x] Watch persists `SETTINGS_JSON` for Android relay (Task 2/4 inbox + `persist_write_string` or chunked persist)
- [x] `pebble build` succeeds
